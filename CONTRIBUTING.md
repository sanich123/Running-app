# Contributing to Runich

Спасибо за вклад в Runich. Перед началом работы настройте локальную среду по инструкции в [`README.md`](./README.md).

## Рабочий процесс

1. Создайте ветку от `develop`:

   ```bash
   git switch develop
   git pull --ff-only
   git switch -c feature/<short-description>
   ```

2. Делайте небольшие тематические коммиты.
3. Перед отправкой изменений запустите проверки.
4. Отправьте ветку и создайте pull request в `develop`, если задача не требует отдельного согласования.

## Проверки перед PR

```bash
yarn tsc --noEmit
yarn eslint .
yarn test
```

Все тесты должны проходить. Если проверка невозможна из-за окружения, укажите причину в описании PR.

## Требования к изменениям

- Сохраняйте TypeScript-типизацию и существующие алиасы импортов.
- Для отдельной страницы с запросом используйте явные состояния загрузки, успеха и ошибки.
- Ошибки важных асинхронных операций показывайте пользователю через `errorToast`.
- Ошибки загрузки страницы должны содержать понятное сообщение и возможность повторить запрос.
- Не блокируйте старт активности оптимизацией батареи: обязательны foreground/background-разрешения, а оптимизация остаётся рекомендацией.
- Не добавляйте секреты, токены или локальные `.env`-значения в Git.
- Новые визуальные компоненты оформляйте через существующие theme tokens, цвета и размеры проекта.
- При изменении маршрутов, permissions или native-конфигурации добавьте описание ручной проверки.

## Pull request

PR должен содержать:

- краткое описание проблемы и решения;
- список пользовательских изменений;
- сведения о ручной проверке, если затронуты iOS/Android, карта, разрешения или фоновые задачи;
- результаты `tsc`, ESLint и тестов;
- скриншоты или короткое видео для заметных UI-изменений.

Рекомендуемый заголовок — короткое описание результата, например `fix: handle incomplete activity route data`.
